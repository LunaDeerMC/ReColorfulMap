# 运行、收费与交付恢复

本次优化不改变 PNG 目录或物品路径 PDC 格式。已使用路径格式的数据无需再次迁移；
ColorfulMap 2.3 的升级仍需按 [存储说明](storage.md) 停服迁移。

## 生成与收费

`/tomap <URL> [比例]` 提交后台任务。同一玩家同时只能有一个生成任务，全服默认允许 2 个工作线程和 16 个等待任务。
`/mapmanage status` 查看当前任务，`/mapmanage cancel` 取消下载或生成。
已完整保存的结果会保留为待领取记录；取消不会删除已经交付的地图。

收费只有一种规则：首次交付新生成的地图画时，按 `列数 × 行数 × economy.cost-per-map` 一次扣款。
例如 2 × 3 的图片、每块 100，则整幅收费 600。取下、移动和重新放置完全免费。
启用收费需要 Vault 或 VaultUnlocked，以及提供经济服务的插件。

任务提交时会固定本次使用的配置。玩家离线或余额不足时，完整 PNG 和生成报价保存在待领取记录中，
玩家上线或补足余额后通过 `/mapmanage list` 和 `/mapmanage claim <UUID>` 领取。
后来修改单价不会改变这幅画的生成报价；已确认付款且尚未交付的地图不会再次扣费。
下载、解码失败不扣款。扣款后、尚未修改背包的失败会尝试退款。
库存操作抛出异常、满背包后的地面掉落被取消，或交付后记录保存失败时，
保留已付款状态并要求核对，不自动退款或重发：其他插件可能已经转移物品，不能仅凭掉落失败确定未交付。
退款结果不确定时也需要管理员核对。

## 交付记录与恢复

`plugins/ReColorfulMap/deliveries/<UUID>.properties` 为每幅新生成地图保存一份小型交付记录，
包括所有者、生成报价、付款状态与交付状态。它不保存地图 ID，也不参与 PNG 路径解析或墙面显示。
世界、玩家数据、`maps` 与 `deliveries` 应一起备份和恢复。

写入记录后才执行对应的扣款或物品交付。正常重启可以继续领取未交付结果，已经交付的记录拒绝重复领取。
插件、经济插件和 Minecraft 世界保存无法组成一个原子事务：如果服务器恰好在扣款或交付期间崩溃，
记录可能无法确定外部操作是否完成。此时保留图片并停止自动重试，由管理员核对，避免重复收费或发物品。
例如物品已经交付但玩家存档尚未落盘的情况，需要结合世界备份处理，不能只根据交付记录自动重发。

玩家命令需要 `recolorfulmap.manage`（默认所有人拥有）。以下命令另外需要 `recolorfulmap.admin`（默认 OP）：

| 命令 | 用途 |
| --- | --- |
| `/mapmanage inspect <UUID>` | 查看所有者、报价与付款/交付状态 |
| `/mapmanage recover <UUID> <在线玩家> confirm` | 恢复已有图片的交付；已有记录时仅允许原所有者继续领取 |
| `/mapmanage resolve <UUID> paid confirm` | `CHARGING` 时确认已扣款，或 `REFUNDING` 时确认退款未到账、原扣款仍有效 |
| `/mapmanage resolve <UUID> unpaid confirm` | `CHARGING` 时，确认经济插件没有扣款 |
| `/mapmanage resolve <UUID> refunded confirm` | `REFUNDING` 时，确认退款已经到账 |
| `/mapmanage resolve <UUID> pending confirm` | 核实未交付、付款状态已明确后，允许原所有者重新领取 |
| `/mapmanage resolve <UUID> delivered confirm` | 核实物品已经交付后，将交付记为完成 |

`resolve` 只修改记录，不转移金钱或物品。付款结果不确定时，先核对经济插件日志并解决付款状态，
再决定是否允许领取。已标记 `DELIVERED` 的记录不能重置。
没有交付记录的旧图片只有管理员显式恢复时才会建立免费领取记录；
执行前须确认背包、容器及墙面不存在仍可使用的同源物品，插件不能扫描离线玩家和全部未加载区块确定这一点。

## 配置与下载限制

配置读取先完成校验再整体生效。格式错误、重复 YAML 键、无效数值或错误语言文件不会覆盖原文件，
失败的重载保留旧配置；首次启动遇到这些问题时插件停止启用。
旧版配置仍可读取，缺少的新字段使用默认值，不自动改写现有文件。
`generation.workers` 与 `generation.queue-capacity` 修改后需要重启；其他运行设置支持重载。

默认限制为下载 32 MiB、原图 1600 万像素、连接 10 秒、读取空闲 15 秒、下载总计 60 秒、最多 5 次重定向。
下载流按实际字节计数，原图尺寸在完整解码前检查，缩小比例不会绕过原图像素限制。
白名单按完整协议、主机、端口和路径段匹配，并检查每次重定向；空列表允许任意 HTTP(S) 地址。
仅主机名的规则允许 HTTP 80 / HTTPS 443，其他端口需要明确填写；完整 URL 规则还限制协议。

## 地图显示与存储开销

原生地图 ID 在同一次运行中按图片路径和地图所属世界复用，旧物品被读取时也会登记已有 ID。
因此通常的反复取回、重放不会每次创建新地图 ID。重启后按已加载物品逐步恢复登记，
尚未发现的旧 ID、跨世界首次使用和管理员复制可能仍会产生新 ID；不会主动删除原生地图存档。

墙面操作先在后台准备图片资料，再在玩家或实体所属线程重新检查框架、手持物品和保护插件权限后提交。
分块按客户端需要加载，缓存与读取队列均有限额，不预先把整幅大图的所有分块塞进缓存。
首次放置或冷启动后的分块可能需要数秒逐步显示，具体时间受服务端原生地图刷新间隔影响。
图片目录的尺寸资料也会缓存；修改目录后再次后台读取会检查目录变化，删除图片会使相关缓存失效。
已发布的 PNG 按不可变文件使用；直接覆盖同名文件不会保证立即刷新已有画面，手工修复图片应停服后进行。

潜影盒、收纳袋等物品容器自然消失或掉出世界时，会递归删除里面地图的图片数据。
容器受到伤害时可能释放内部物品，因此不直接递归删除；后续内部地图自身真正销毁时再处理。
创造模式删除与 `/clear` 等没有通用销毁事件的操作仍不自动删图，详见 [删除范围](storage.md#放置取回与自动删除)。
