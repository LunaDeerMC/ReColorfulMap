# 复制与数据生命周期（5.0.1）

5.0.0 将某个物品的销毁等同于整幅图片数据不再使用。同源副本共享一个目录，因此销毁其中一份会使其他副本失效；同幅墙面的一个分块也会触发整目录删除。

## 指令复制

手持整幅地图画或单块，执行 `/mapmanage copy`。需要 `recolorfulmap.manage` 和 `recolorfulmap.copy`，两项默认开放。
复制免费，不扣经济余额、不消耗空白地图、不改变原物品。每次复制一份，需要一个空背包槽位。

整图副本将现有 PNG 复制到新的 UUID 目录，并使用新原生地图 ID；复制不使用硬链接或共享文件。
单块副本只需要该块的 PNG，成为新的 1×1 画作，因此原阵列中其他块损坏不会妨碍复制它。
源目录没有历史 `raw.png` 时保留这一事实，复制仍可使用有效缩略图和分块，不伪造原始图片。

图片复制先在有界后台队列中完成，再回玩家所属线程检查主手、选中槽位、在线状态和目标空槽。
这些状态变化或磁盘复制失败时不发物品，原图不消耗。每位玩家同时只处理一项复制。
部分背包写入失败会尝试恢复目标空槽；若恢复结果也不确定，保留新图片并记录日志，不删除可能已经交付的数据。
其他插件可调用 `getArtworkCopyService().copy(...)`，提交回调须遵守其事务契约。

## 支持范围

仅支持指令和上述公开服务复制。工作台、制图台的图片地图复制配方会被取消，材料保持原状。
普通原版地图及非复制配方不受影响。

创造模式复制、复制潜影盒/收纳袋中的图片、其他插件直接克隆 `ItemStack` 或 PDC 均不在支持范围。
这些方式仍可能产生共享路径，并绕过独立所有权约定；本版不实现跨包创造背包事务，也不拦截正常创造背包移动。
不能把“不支持这些复制方式”理解为能够识别并修复它们产生的全部共享引用。

## 删除与旧数据

新生成画作和指令副本带有目录内 `.independent-artwork` 标记。该标记不是全世界引用计数。
独立整图真实销毁时删除自身目录；独立分块销毁时只删除该块，最后一块消失后清理剩余图片。
其他独立副本的 UUID、图片和地图物品保持有效。普通拾取、放置、取回和区块卸载不删图。

旧 ColorfulMap 迁移数据保留原 map ID、PDC 路径和共享关系，不写独立标记；旧无标记目录在物品销毁时继续保留。
不要手工给旧共享目录添加标记。`/cleancolorfulmap` 仍只清理私有临时文件，不清除这些历史目录。
复制增加磁盘文件和原生地图 ID；回退应同时考虑新物品存档与图片目录，不能只换 JAR。
