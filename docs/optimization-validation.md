所有实服测试使用上述同一 SHA 的 JAR，服务端为 Paper 26.2 build 133、Folia 26.2 build 7，Java 25。

| 验证组 | 结果 |
| --- | --- |
| Paper 原有玩法矩阵 | 30 项通过：四方向、任意分块取回、保护、回滚、满背包、拾取与销毁等 |
| Paper 冷重启 | 6 项通过：逐块彩色像素与原路径恢复，交付失败、物品合并和取消销毁等 |
| Paper 优化功能 | 26 项通过，包含真实 Vault 收费、136 分块大图、配置、容器与离线领取 |
| Folia | 16 项通过：所属线程检查、整幅取放、地图 ID 复用、像素、重启和销毁 |
| 迁移后混合存档 | 3 项通过：容器与墙面、逐块像素、取回与重放 |
| 原始 ColorfulMap 2.3 来源数据 | 5 项通过：12 张 PNG 哈希一致、旧背包和嵌套容器、显示及整幅取放 |

收费实测使用真正注册到服务管理器的 Vault 经济实现：2 × 2 地图按每块 10.5 收费 42，一次生成只扣一次。
连续三次取回和重放免费，缩略图与四个分块的地图 ID 均保持不变。
余额不足、取消下载、下载失败、结果不确定的交付及重复领取均验证了相应付款与物品数量。
离线完成的结果在冷重启后可以领取；即使重启时关闭新生成收费，旧结果仍按原报价只扣一次，新生成地图免费。

136 分块地图在真实网络客户端中完成全部分块显示，从最后一个分块整幅取回并重新放置，所有已登记 ID 复用。
普通框和发光框分别验证拆除支撑块触发的原版物理破坏：相邻保护生效、掉落取消时恢复整幅墙面、成功时返回正确框材质。
潜影盒、收纳袋及嵌套容器分别验证自然消失、掉出世界的图片清理，以及受伤销毁时释放的内部地图仍可拾取且保留图片。

首次像素检查暴露了测试取样问题：旧驱动在放置后 700 毫秒即保存像素，而当前 Paper 设置下，
懒加载空首帧之后约 2.5 秒才再次执行墙面地图渲染。驱动现逐块等待完整彩色像素并稳定后再比较哈希。
旧版迁移墙面在自然等待后，四个分块均与参考彩色像素哈希一致，未调用强制发送地图 API。

另外修正了测试观察器的两处时序假设：腾出背包后物品可能已自然拾取；容器原版销毁事件发生前，内容可能已经释放并被拾取。
改为使用真实拾取事件、实体 UUID 和预先记录的容器路径验证，相关失败记录与分阶段复测信息保留在验收包中。
这些调整均未修改生产代码或测试 JAR。

## 验证边界

测试使用仅监听本机的隔离服务端和协议客户端，不连接正式服务器。客户端校验地图像素数据，未使用图形客户端人工目视验收。
测试经济插件实现真正的 Vault 服务接口；保护和交付拦截使用真实事件链，不代表已安装并验证所有第三方插件组合。

PNG、交付记录、经济插件数据库及 Minecraft 世界保存不属于同一个事务。
异常交付状态需要核对，已经交付但玩家存档尚未保存时崩溃仍需结合整组备份恢复。
配置、命令与这些边界的具体处理见 [运行与恢复说明](runtime.md)。
