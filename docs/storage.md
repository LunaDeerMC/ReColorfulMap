# 地图画存储与 ColorfulMap 2.3 升级

ReColorfulMap 直接读写 ColorfulMap 2.3 的 PNG 文件和地图 ID 索引格式。
图片字节只保存在插件目录中，不写入世界、展示框或地图物品的 PDC。
启动时加载索引，PNG 在需要显示或操作地图画时读取，避免启动时解码全部图片。
渲染使用最多 128 张图片的共享缓存；下载、图片文件生成和放置时的分块读取、索引写入在后台执行。
地图物品及展示框的变更仍在服务器对应线程上完成，文件保存成功后才提交放置。

## 升级步骤

1. 停止服务器，备份世界、玩家数据和 `plugins/ColorfulMap/maps`。
2. 移除 ColorfulMap 2.3 插件 JAR，安装 ReColorfulMap，避免两个插件同时处理地图事件。
3. 将旧插件的整个 `maps` 目录复制到新插件目录，得到以下路径：

   ```text
   plugins/ReColorfulMap/maps/maps.yml
   plugins/ReColorfulMap/maps/<UUID>/thumb.png
   plugins/ReColorfulMap/maps/<UUID>/0_0.png
   ...
   ```

4. 保留原世界存档及其中的原生地图 ID 数据，再启动服务器。无需转换文件或运行迁移命令。

存储路径以插件实际数据目录为准，由 `getDataFolder()` 获取，默认是 `plugins/ReColorfulMap`。
插件名称保持 `ReColorfulMap`，无需为迁移修改插件名称或统一目录大小写。
必须同时复制 `maps.yml` 和所有 UUID 子目录，不能只复制 PNG。
上述流程适用于原服务器升级：索引以世界名称和地图 ID 关联物品，复制到另一个没有原地图数据的服务器
并不能恢复原有物品。升级时应保留世界名称。

旧版 `colorfulmap.*` 权限节点需要按 README 中的指令表调整为 `recolorfulmap.*`。
本仓库之前实验性的 PDC 图片存储格式已完全废弃，不读取或转换其中的图片数据。

## 目录与图片格式

```text
plugins/ReColorfulMap/
└── maps/
    ├── maps.yml
    └── <地图画 UUID>/
        ├── raw.png
        ├── thumb.png
        ├── 0_0.png
        ├── 1_0.png
        ├── 0_1.png
        ├── 1_1.png
        └── meta.txt       # 旧版可能留下的可选日志
```

每幅地图画有独立 UUID，与 Minecraft 的地图 ID 无关。

| 文件 | 含义 |
| --- | --- |
| `raw.png` | 下载的原始图片，尚未应用生成时指定的缩放比例 |
| `thumb.png` | 整幅地图画物品使用的 128 × 128 缩略图 |
| `<x>_<y>.png` | 128 × 128 图片分块；图片左上角为 `0_0`，向右增加 x、向下增加 y |
| `meta.txt` | ColorfulMap 2.3 放置时写入的玩家、时间、位置、尺寸等日志，可缺省 |

分块是在缩放后的图片居中补齐到 128 的整数倍后切分的。
阵列大小根据完整的分块矩形确定；`raw.png` 是缩放前的图片，不能用它的尺寸推断阵列大小。
`meta.txt` 只记录旧版最近一次放置，不参与地图身份识别、显示或取回。

## 地图 ID 索引

`maps/maps.yml` 保存世界名称、地图 ID 和相对于插件数据目录的图片路径：

```yaml
world:
  '123': maps/b44b66b1-1260-43a6-91bb-aeb1f3dca74d/thumb.png
  '124': maps/b44b66b1-1260-43a6-91bb-aeb1f3dca74d/0_0.png
  '125': maps/b44b66b1-1260-43a6-91bb-aeb1f3dca74d/1_0.png
world_nether:
  '126': maps/b44b66b1-1260-43a6-91bb-aeb1f3dca74d/0_0.png
```

路径中的 `maps/` 前缀保持不变，因此目录从 `plugins/ColorfulMap` 复制到
`plugins/ReColorfulMap` 后无需修改索引。一个 PNG 可以被多个地图 ID 引用。
服务端初始化地图时，插件按地图自身的世界和 ID 恢复图片渲染，而不是按持有玩家所在的世界查找。

## 旧物品兼容与阵列操作

ColorfulMap 2.3 没有在地图物品上使用 PDC：

- 未放置的整幅地图画使用缩略图地图 ID，唯一一行 lore 为 `size: 宽x高`，
  该行的 Adventure 悬停文本保存地图画 UUID。新版本支持这种物品。
- 旧版已悬挂的分块没有 lore 或 PDC。新版本通过地图 ID 索引中的路径识别 UUID 和分块坐标，
  因此不需要重新生成或重新放置即可显示。
- 取回旧阵列时，通过分块坐标、阵列尺寸和展示框朝向确定整幅画的位置，再核对每个展示框中的图片身份与坐标。
  完整的旧版墙面阵列可以整幅取回；阵列缺失或混入其他图片时不能作为完整地图画取回。
  已确认不成完整阵列的分块仍可按原版方式单独取出，不修改相邻展示框。
  如果相关区块尚未加载，或 Folia 当前线程无权访问整个区域，则保留阵列并提示重试。

放置和取回不删除 PNG，也不删除原有地图 ID 映射。
这允许同一幅地图画的多个副本继续显示和使用，避免一次操作使背包或箱子里的其他副本失效。

## 清理与备份

`/cleanColorfulMap` 只清理本插件写入失败留下的临时文件，不删除地图画、缩略图或地图 ID 映射。
插件无法通过当前在线玩家和已加载区块证明一幅画没有其他引用，因此不会自动回收“未放置”或“未显示”的图片。

备份时应将整个 `plugins/ReColorfulMap/maps` 与世界、玩家数据一同保存。
仅备份插件目录会缺少地图物品和原生地图 ID 数据；仅备份世界则缺少插件保存的 PNG 与索引。

## 验证范围

旧格式依据用户提供的 `ColorfulMap-2.3.jar` 静态反编译核对，未执行旧插件。
文件读写和兼容解析的自动化检查不能代替真实服务端中的渲染、展示框事件及重启恢复验证。
本文不代表已通过 Minecraft 客户端、Paper 或 Folia 的实服验收。
目前整幅取回仍同步保存一次缩略图地图 ID 索引；对于特别大的 `maps.yml`，这一步的耗时需在实际服务器上评估。

建议在世界副本中完成以下升级验收：

1. 使用旧版留下的完整 `maps` 目录及世界存档启动，检查旧墙面地图、背包和箱子内的缩略图显示。
2. 放置旧版整幅地图画，取回完整旧阵列，再重新放置；检查图片方向和阵列尺寸。
3. 保留同一幅画的另一个副本，确认放置、取回及执行清理命令后它仍可使用。
4. 重启服务器，再检查显示和取回；同时确认新的图片文件及地图 ID 索引已保存。
5. 在阵列缺失或分块被替换时尝试取回，确认不会将不匹配的展示框内容清空。
